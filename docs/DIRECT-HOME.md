# Homeキーの直接起動（1.0.5）

## 表示検知との違い

1.0.4のHomeRedirectServiceは純正ホームの画面表示を検知してQuiet TVを開くため、純正画面が一度表示されます。HomeKeyServiceはHomeの押下を先に処理し、純正ホームへの入力を消費してQuiet TVを開く任意サービスです。両者は別々に有効・無効を選べます。

## 権限と挙動

- HomeKeyServiceは `canRequestFilterKeyEvents` と `flagRequestFilterKeyEvents` を要求します。前の表示検知サービスへの同意とは権限範囲が異なります。
- Androidの仕組み上、キーイベントを受信します。Home以外はfalseを返して通過させます。入力値のログ・記録・保存・送信は行いません。
- 最初のHome押下で起動し、リピートと対応する解放を消費します。起動例外時は処理状態をリセットしてOSへ任せます。
- Homeの長押し・連打もQuiet TV起動として扱います。Homeキーの既存の長押し・ダブルタップ機能は置き換わります。
- 画面内容の取得権限は要求しません。音声・HDMI設定は変更せず、純正ホームと初期設定アプリは有効のままです。
- インストールだけでは有効になりません。ユーザー補助設定での明示的な有効化が必要です。

## 現時点の検証

実機の既存Button MapperはHomeキーを追加一覧に登録できませんでした。既存のBUTTON_6（193）と音量ボタンの設定は変更していません。

直接Home処理は別の任意サービスとして実装しています。Homeの押下・解放の対、リピート、他キーの通過、例外時のリセットをJavaテストで確認しました。

2026-10-24に追加同意を得て有効化しました。`dumpsys accessibility` でcapabilities=8、キー処理フラグを要求したサービスが稼働していることと、既存のButton Mapper・HomeRedirectServiceが保持されていることを確認しました。

設定画面から物理Homeキーを押す実機テストで、ユーザーが「Quiet TVが直接開きました」と回答しました。同じテストの前後の画面遷移ログを比較し、純正HomeActivity / VanillaModeHomeActivityのresumeが0件であることを確認しました。DashboardHandlerは表示でき、戻るキーでQuiet TVへ戻ります。

再起動・ファームウェア更新後や、すべてのアプリからの動作は未検証です。物理Homeキーと同じ経路を通らないADB入力などでは、表示検知側のフォールバックで切り替わる場合があります。

## 元に戻す

直接処理だけ止める場合は「Quiet TV Homeボタン直接起動」を無効にします。表示検知の「Quiet TV ホーム切替」を残せば、従来の方式に戻せます。

純正ホームへ完全に戻す場合は両サービスを無効にするか、`scripts/restore-google-tv.sh` を実行してください。このスクリプトは他のユーザー補助サービスを保持します。
